## 2. 架构（共享 trunk + 5 专家输出头 + shared 头）

```
obs ──> shared trunk (C1 初始化, Muon) ──┬─> score head(family) ─> logits
                                          └─> value head(family) ─> v
family id ──> hard router (查表，5:shared)
```

- **专家范围**：先做**输出头级 MoE**——每个专家 = `score1/score2`（策略）+ 
  `value1/value2`（价值）两组 MLP；trunk、`dec/opt/q`、`oracle/aux` 全部共享。
  这是“每个 family 独立的策略和价值网络”的最小忠实实现；全链路 per-family
  （dec/opt/q 也独立）留作 v2。
- **硬路由**：`family_id ∈ {0,1,2,3,4,5}`，5 = shared；训练期 env 已知每方卡组，
  按 `deck_idx → family` 查表；双方各自按自己的卡组路由。
- **前向实现（compute-all-select）**：6 组头对全 batch 都算（头很小，6× 可忽略），
  再按每行的 family_id gather；反向只对选中专家的权重回传梯度。避免 per-row
  索引权重 gather 的复杂度。
- **参数注册**：append-only。shared 沿用现有名字（`score1_w`…`value2_b`），
  新增 `e0_…`–`e4_…` 各 8 个参数 → PT_PARAMS 120 → 160。
  `native/tools/native_weights.py::param_order` 同步，旧 C1 blob 仍可直接导入
  （新参数用 shared 头拷贝初始化）。

## 3. 路由输入（family id）与 obs

- 不扩 `OBS_SIZE`。env 的 obs 布局里有 reserved 全零块 `PT_TRANS`
  （64×24）与 `PT_THREAT`（64×8），当前约定“encoder 不写、model 不读”。
  pilot 把 `PT_TRANS` 的第 0 个 float 改成 family id（0–5），并在
  `native/ptcg/ptcg_env.h` 与 `ptcg_model.cu` 的 offset 常量里同步注释/契约。
- 每行（每个 seat）写自己卡组的 family；WALLY/r4d 两个 manual 卡组按
  `pool_v21_family_map.csv` 的映射（WALLY→lopunny=shared，r4d→crustle=shared）。
- 若后续需要更干净的接口，再把 family 拆成独立 buffer（类似 `league_tag`），
  但 pilot 用 obs 预留槽最小改动。

## 4. 数据与初始化

- 训练池：`decks/pool`（新 1369，famfix2）；C1 只见过旧 616 池（417 card id），
  新池引入 1428 个新 card id → **C1 不能当新池的冻结对手**，MoE 训练从
  self-play 开始。
- 新卡 embedding 初始化：新行用旧行均值 + 小噪声（避免全零/纯随机造成前期
  梯度爆炸）；embedding 保持可训练（Muon，不做 V21 的 AdamW 冷冻）。
- 采样：family-balanced（每族目标质量，族内按 tier/weight 抽 deck）；
  5 个专家族按实际质量、小族保底，避免 expert 饥饿。
- trunk/头初值：旧 C1；5 个专家头初值 = shared 头拷贝（起点与 C1 等价）。

## 5. 训练配置（pilot）

- 双方都训练：同一模型两个 seat，self-play；不挂 frozen bank（pilot 不需要，
  也避开 bank 的 row-static/16-bank 限制）。
- 优化器：**C1 原样 Muon（不 split）**；不要重蹈 V21 的 embedding/head AdamW 冷冻。
- 有效 batch：`--accum-minibatches 8`（C2 已验证的 SNR 杠杆）。
- lr：3e-5 cosine；ent：1e-4 → 1e-5 anneal。
- 稳定性（可选单变量）：per-step KL trust region（对上一时刻策略）或 EMA champion；
  pilot 先不加，留作 S2 之后的对照。
- value：self-play 两侧都是 learner 行，value 正常学习双方回报（不需要 C2 的
  frozen-row 排除）。

## 6. 评测

- **per-family 内部标尺**：每个专家族 1–2 副 anchor deck，对“冻结的上一版
  champion 快照”做 arena（temp 0），看族内胜率与族间方差；shared 族同样抽 anchor。
- **旧池回归**：对 `opp_alakazam/dragapult/blaziken` 的 arena，监控是否因新池
  训练掉 C1 水平（阈值：不低 C1 −.02）。
- 训练内：per-family `lgw`（对阵当前对手的胜率）、ent、expert 使用率；
  expert 使用率必须与采样份额一致（路由正确性）。
- 新池没有外部 agent 基准，第一版只能相对比较（对快照/对旧 C1 的旧池表现）。

## 10. 实施记录（2026-11-21 晚，v1）

- **专家范围**：每个专家 = `score1/score2`（策略）+ `oracle_v1/oracle_v2`
  （PPO 价值；`value1/2` 是 blind aux，保持 shared）。共 5×8=40 个新参数，
  PT_PARAMS 120→160，append-only，旧 C1 blob 仍是合法前缀。
- **路由**：`obs[PT_OFF_TRANS]`（trans 预留块第 0 个 float）存 family id，
  `0 = shared`（torch/python 零填充行默认走 shared），`1..5 = abra/dragapult/
  excadrill/shuppet/ogerpon`。env 的 `encode_row` 按 `deck_idx[seat]` 查
  `native/ptcg/family_map.h`（1369 项，按 tables blob 顺序生成）。
- **前向**：`PTCG_MOE=1` 时 6 组头全算（shared + 5 experts），每行按 family
  gather；反向按 family mask 每组头、输入梯度用 `pt_linear_bwd_acc` 累加。
  未开 `PTCG_MOE` 时原路径逐位不变。
- **初始化**：`native/tools/expand_moe_init.py` 把 C1 120 参数 blob 扩成 160，
  专家头 = shared 头拷贝（step 0 行为等价 C1）。
- **训练**：新 1369 池、self-play（`--mix-self 1.0`）、无 frozen bank、
  `--deck-weights-file decks/deck_weights_v21_hybrid.req`、Muon 不 split、
  accum 8、lr 3e-5 cosine、ent 1e-4→1e-5、50M。
- **验证**：
  - `model_parity` 在 `PTCG_MOE=0` 与 `PTCG_MOE=1`（parity 行 family=0）都
    `PARITY OK`（KL ~1.9e-10，argmax 100%）；
  - 10-epoch 冒烟：SPS 18.3k、vram 42.2G、无 NaN；5 个专家的 score/ov 头
    |delta| 0.0018–0.0059（每个专家都拿到梯度）；
  - 50M pilot `v21_moe5_50m` 2026-11-21 23:38 发车，25M/50M checkpoint 各
    arena 100/200 局（torch 只走 shared 头；per-family torch 路由待补）。
- **已知限制**：
  - torch 前向仍是 shared 路径，per-family 评测需要补 torch 路由；
  - 新池没有外部 agent 基准，当前 WALLY arena 只测 shared 头 + trunk；
  - 全模型 Muon 在固定卡组 C2 会漂，但 MoE 是多族 self-play（接近 C1 的
    训练分布），pilot 的 25M 指标是第一个判据。

## 11. 50M pilot 结果（2026-11-22 00:23）

`v21_moe5_50m`（50M，~epoch 95）完成，WALLY/shared 路径 arena：

| 点 | ak | dra | bla | mean | n |
|---|---|---|---|---|---|
| 25M | .560 | .730 | .670 | .6533 | 100 |
| 50M | .605 | .740 | .620 | **.6550** | 200 |
| C1 基线 | .579 | .698 | .673 | .650 | 202 |

- **无崩溃、无整体提升**：50M .6550 ≈ C1 .650。shared 头 + trunk 在新池
  self-play 下站住了，但 WALLY 属于 shared 族，这个指标看不到专家头的作用。
- 训练侧：SPS 18.4k（比 C2 的 19.1k 低 ~4%），vram 42.2G；偶发 vf 尖峰
  （epoch 65 vf 18.5、epoch 76 vf 1.88），同时 klskip>0（该步被 KL guard
  跳过），随后立刻回到 .03——是瞬态 batch/守卫行为，不是发散。
- **专家路由数值 parity**：native `PTCG_MOE=1` + obs family=1 对 torch
  `eval_family=1`，`PARITY OK`、argmax 100%（score + oracle_v 专家头都验证）。
- 下一步判据：per-family A/B（5 族 anchor deck，expert vs shared，3×50 局），
  结果在 `logs/moe5_perfamily.md`。专家族内优于 shared 才说明 MoE 头有效；
  若持平，则 50M 的瓶颈在共享数据/对手，而不是头容量。

### 11.1 Per-family A/B（50M，5 族 real anchor，expert vs shared，3×50 局）

| family | shared | expert | delta |
|---|---|---|---|
| abra | .5067 | .5600 | +5.3pp |
| dragapult | .6667 | .6133 | −5.3pp |
| excadrill | .0400 | .0400 | 0（地板） |
| shuppet | .1400 | .1533 | +1.3pp（地板） |
| ogerpon | .5467 | .5667 | +2.0pp |

每格 150 局，CI ≈ ±8pp；**50M 的专家头没有可检测的族内增益**
（4 个非地板族平均 +0.8pp）。原因大概率是：每个专家只分到 ~5–12% 的行，
50M 不足以让头级专家拉开差距；共享 trunk 承担了主要学习。
结论：头级 MoE 的 50M pilot“能跑、不崩、路由正确”，但“专家增益”未兑现。
下一步优先级：① 200M 延长看 delta 是否随数据量拉开；② 专家扩到全链路
（dec/opt/q 也 per-family）或给家族行加权；③ 若仍持平，头级 MoE 不是瓶颈，
转 C1-adapt 或改对手/数据机制。详见 `logs/moe5_perfamily.md`。

### 11.2 200M 延长结果（2026-11-22 03:35）——回退，弃用

从 50M ckpt 续 150M（lr 1e-5 cosine、ent 1e-5、accum 8、self-play）：

| 总步数 | WALLY mean (200g) |
|---|---|
| 50M（起点） | .6550 |
| 100M | .6017 |
| 200M | **.5567** |

- per-family 训练内胜率（pfw）在 250 个 epoch 里几乎不动（shared ~.38、abra ~.66、
  dragapult ~.72、excadrill ~.35、shuppet ~.28、ogerpon ~.65），说明回退不是单族崩，
  而是 shared 策略整体相对旧池 meta 对手变差。
- 200M per-family A/B（300 局/格）：abra .5200/.4267（expert −9.3pp）、
  dragapult .5633/.5733（+1.0）、excadrill .0367/.0567（+2.0，地板）、
  shuppet .0633/.0800（+1.7，地板）、ogerpon .4767/.4667（−1.0）；
  非地板族平均 **−3.1pp**。专家头仍然没有优势。
- 结论：**200M 延长线弃用**；MoE 实验以 50M ckpt 为基座继续，不再加步数。
  下一批实验改为“训练动力学”单变量（head-only 冻 trunk / accum16 / ref-KL 锚 /
  家族加权 / family-matched 对手）在 50M 内对照。
- 评测 bug 记录：`m=eval_point` 里函数内部 `log|tee` 污染了命令替换的 stdout，
  早停比较抛异常未触发；后续脚本已改为日志只写文件、stdout 只留返回值。

### 11.3 7 小时训练动力学实验（2026-11-22 04:30–11:00）

六臂（A head-only / B accum16 / C ref-KL / D head-only+家族×2 / E head-only+
family-matched+WALLY 槽 / F full+match）+ 200M 延长，全部从 50M ckpt 起 50M。
完整数据与诊断见 `docs/moe5_7h_report_20261122.md`。三条硬结论：

1. **全模型延长在弱 advantage self-play 下漂移**：WALLY .655 → 200M .557；
   head-only 只掉到 .635（最小）；accum16 .620；ref-KL .585。冻结 trunk 是
   最有效的止漂手段，但只止血、不产生增益。
2. **头级专家的增益未坐实**：非地板族 expert−shared 在 −3.1 ~ +3.3pp 之间，
   全部在噪声内；E 的 WALLY 槽 seed 0 +5.8pp、seed 7 −0.5pp（合并 +2.6pp，
   CI ±3.9）。family-matched + WALLY 槽值得保留，但需要全链路专家/更大样本
   才能变成稳定增益。
3. **full-model 下同样的 family-matched + WALLY 槽没有专家增益**
   （F: WALLY −1.0pp），支持“冻 trunk 是专家信号出现的必要条件”。
