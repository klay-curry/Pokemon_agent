## 4. 诊断：与 C2 同源，但“解药”只对了一半

1. **表现符合 advantage 稀疏 + 归一化更新 + 全模型漂移**：
   - self-play 双方同策略，期望胜率 50%，per-decision advantage 弱；
   - 训练内 per-family 胜率 250 epoch 几乎不动（pfd 平坦），而外部 WALLY
     持续下降——是“没有信号、但参数在动”的典型漂移；
   - 全模型（B/C/200M）回退 3.5–10pp；**冻住 trunk（A/D）只回退 2–4pp**，
     这是对“全模型更新是漂移源”的直接支持。
2. **但 head-only 只止血、不产生专家增益**：A 的专家 delta +3.3pp 仍在噪声内。
   头级专家（score+oracle_v）的表达力太小；每个专家只分到 ~5–12% 的行，
   50M 内无法拉开。
3. **accum 16 与 ref-KL 都不是解药**：B 比 200M 的 100M 点好 ~1.8pp，
   C 反而更差（.585）——锚定起点不能阻止策略在弱信号下的随机游走。
4. **家族加权/匹配对手（D/E/F）尚未看到增益**（D +1.3pp）；E/F 待评测。

## 6. 建议

1. **不要再用“全模型 + 加步数”训 MoE**：200M 的证据明确（.655→.557）。
2. **头级 MoE 的增益上限低**：下一版把专家扩到全链路（dec/opt/q 也 per-family）
   或至少 per-family 的 dec/opt，再配合 head-only + 家族匹配对手。
3. **C2 保底不受影响**：旧 C2 recipe（frozen C1 对手）仍是 .68–.70 的保底；
   MoE 权重只在 E/F 证明 WALLY 专家 > shared 后才值得接入。
4. 训练动力学结论（可复用）：**稀疏 advantage 下，冻结 trunk 比调 lr/batch/ref-KL
   更能阻止漂移；但增益要靠更大的专家容量/更多族内数据。**

## 7. E/F：WALLY 槽（槽 3 = lopunny）的关键正向结果

`v21_moe5_ho_match_50m`（E = head-only + 专家族×2 + family-matched 对手 +
槽 3 = WALLY 族），50M：

| deck | shared (family 0) | expert (family 3) | delta | n |
|---|---|---|---|---|
| WALLY | .6017 | **.6600** | **+5.8pp** | 600 |
| LOPUNNY r4d_016 | .5533 | **.6300** | **+7.7pp** | 300 |

- seed 0 的两个 lopunny 系 deck 一致正向；但 **seed 7 的确认没有复现**：
  shared .6433（.610/.770/.550）vs expert .6383（.540/.795/.580）→ **−0.5pp**。
  合并两个 seed（1200 局/模式）：+2.6pp，95% CI ≈ ±3.9pp，**不显著**。
- 所以这是一个“有希望但未坐实”的信号，不能当成已复现的专家增益。
- E 的 WALLY expert .6600 追平了基座 50M 单 shared 头的 .6550，而 E 的 shared 头
  只有 .6017——说明“冻 trunk + 族内对手 + WALLY 专属专家”把族内信号集中到了
  专家头上，且没有牺牲 WALLY 的绝对强度。
- 机制解释：head-only 阻止了 trunk 在弱 advantage 下的漂移；family-matched
  对手给专家提供了同族对局（而不是 1215 个 coverage deck 的噪声）；
  WALLY 族占一个专家槽后，learner 的卡组有专门的头，不再和 coverage 族共享参数。
- F（full_model + match）已评测：WALLY shared .5967 → expert **.5867（−1.0pp）**；
  LOPUNNY shared .4967 → expert .5567（+6.0pp，300 局）。**同样的 family-matched
  数据和 WALLY 槽，full-model 下专家没有增益（WALLY 甚至 −1pp）**，而 head-only
  的 seed-0 是 +5.8pp——支持“冻 trunk 是专家信号出现的必要条件”，但增益本身不稳。
